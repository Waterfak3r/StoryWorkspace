# ADR 026：故事大纲是时间作脊的实体-时间-事件导图

## 背景

用户要求故事大纲以思维导图连接实体、时间和事件。这覆盖 [ADR 024](./024-timeline-pipeline-lettering.md) 的主视图（人物泳道 × 事件矩阵，参照 Aeon / Plottr），也补上 [ADR 025](./025-living-outline-referenced-dialogue.md) 已写但未长成导图的活地图。

当前 UI 把三类东西拆成实体芯片货架、节拍横链、角色出场矩阵。连线几乎看不见，时间没有自己的节点。

用户已确认布局：**时间作脊**。不是书名居中放射，也不是自由力导向图。时间先用已有卷/章，不另建「第三天 / 入夜」故事钟。

## 决策

1. **故事大纲主视图是一张导图。** 节点只有三类：时间（卷、章）、事件（一场一事）、实体（角色必上图，地点为环境锚点，被场引用的道具/服饰上图）。边：时间包含（卷 → 章 → 事件）、事件顺序、实体参与事件；有场后补丁再画状态变化。实体不直接连实体。
2. **时间作脊。** 卷 → 章沿阅读顺序展开，可折叠。事件挂在所属章下。实体从参与的事件两侧长出；同一实体多场出场则多条边，点它时高亮整条轨迹。
3. **汇编原则不变。** 真相仍是 Scene + Entity + Story State。`assembleStoryOutline` 只读汇编。不写 `outline.json`。人不在图上凭空建节点或拖连新建关系。
4. **覆盖 ADR 024 的主视图。** 人物泳道矩阵不再是大纲主界面。`timeline.characters` / `intersections` 可继续汇编以免旧测试误伤，但大纲 UI 不再渲染表格、货架或单独节拍横链。
5. **ADR 025 其余条款仍有效。** 对白先确认再引用、Story State、引用不复制。

## 后果

- 大纲 e2e / 截面测试断言时间/事件/实体节点与连线，不再要求泳道单元格。
- 故事世界时钟、图上拖连、可编辑脑图文件仍不做。
