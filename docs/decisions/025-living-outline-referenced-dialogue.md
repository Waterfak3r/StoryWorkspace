# ADR 025：活大纲图、确认对白引用、Story State

## 背景

用户把产品芯收成：实体是可复用单元；大纲图随故事完善；实体引用进漫画，做到风格/人物/情节/逻辑一致。随后补充：生图时的对白也必须引用「已经处理并确定好场景和人物」的台词，禁止生成时再扫一遍剧本。

这覆盖 [ADR 019](./019-story-outline.md)「大纲只是场卡片汇编」的观感，以及当前实现里 `generate-shot` / 描字每次 `extractAttributedDialogue(scene.script)` 的做法。不恢复 SQLite 大纲库。

## 决策

1. **大纲图是只读活地图。** 真相仍是 Scene + Entity + Story State。图由 `assembleStoryOutline` 汇编：事件节点（一场一事）、实体节点、参与边、序列边；有场后补丁时再画状态边。不另存大纲 JSON。人不在图上凭空建节点。
2. **实体必须上图。** 角色必有节点与出场轨迹。地点是事件的环境锚点。道具/服饰被至少一场引用即上图；多场引用时轨迹与角色同等可见。
3. **对白先确认再引用。** 对话处理把台词落到场上：`speakerId` 指向人物实体，`shotId` 指向格。`dialogue.status === "confirmed"` 之后，Compiler / 描字 / Workflow 只读这些行。未确认则本页不对白，**不得**回退去扫 `script`。
4. **Story State 是逻辑一致的落点。** 每场一份场后补丁（实体 outfit / condition 等），标记 Canon 或推断。Resolver 按故事顺序叠 `states.default` + 本场之前的补丁。Compiler 带叠后状态和前情摘要。生成范围（本页）与上下文范围（向前取）分开。
5. **引用，不复制。** 人设不写进 scene JSON；对白不在生图时从正文重抽；prompt 里的说话人必须是已确认实体名。

## 后果

- Workflow「对话处理」成功 = 已有分镜的场完成对白确认，不再等于「剧本里能正则抽出引号」。
- 改剧本不会静默改已确认对白；要更新必须再跑对话处理。
- 大纲 UI 以实体为可点单元；观感另审。
