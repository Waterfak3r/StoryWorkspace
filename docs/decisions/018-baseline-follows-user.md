# ADR 018：产品基线限制随用户补充

## 背景

`mvp.md` 曾把开篇「明确不做」写成冻结表。代理会用旧限制否决用户新范围，或在用户改口后又把原文「恢复」回去。用户要求：限制随其决策补充。

## 决策

1. `docs/product/mvp.md` 是本分支唯一实现基线；其中「当前限制」随用户决策增补或改写。
2. 用户新声明的不做项写入该节；用户明确要做的能力从限制划出并写入必做/切片。
3. 最新用户覆盖优先于 `mvp.md` 旧句、`concept.md` 远期规格、已撤回切片。
4. 改范围先改 `mvp.md` 再写代码。`Agents.md` 只记协作，不另存一份冻结限制表。

## 后果

代理不得说「原文写了明确不做所以不能做」来拒绝用户刚确认的能力；也不得在用户撤回后假装限制从未被用户改过。
