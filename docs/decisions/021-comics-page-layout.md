# ADR 021：Image API 直接生成漫画页

## 背景

用户要求朝漫画方向推进。曾把「页」做成已有静帧的 CSS 2×2 拼贴。用户明确否定：调用 Image API 时直接生成漫画，不是先出四幅独立图再拼；若必须用已有图，也要合成**一张**叙事上连贯的页图。

## 决策

1. **取代** ADR 017 第 3 条、ADR 019「不做页排版」，并**作废**本 ADR 初版「只读 CSS 拼贴、不画整页 PNG」。
2. 生图单位是**一页漫画、一次 Image API、一张 PNG**。同一场内按镜序每 4 镜一页；编译器把这些镜写成一页多格（阅读顺序、分隔、同一角色/风格），禁止「四张互不相关的静帧」。
3. 页图写入 `outputs/comics/pages/<pageId>/<runId>.png`。页上未锁定的镜共享该 `selected_image`。
4. 遗留的不同静帧：汇编时合成一张带分隔与阅读顺序的页图（1 格铺满；2 格上下；3 格上二下一；4 格 2×2），不是前端四张 `<img>`。
5. Outputs 展示 `page.pageImage` 这一张图。不对白气泡 / 描字 / 出血 / PDF。不恢复视频。

## 后果

- `mvp.md` 漫画页 = 生图即漫画页，不是静帧拼贴。
- 单镜 Workflow 重跑会重画该镜所在整页。
