# ADR 030：通用 LLM 理解契约

## 背景

故事工作流的核心资产是实体、事件、时间和确认对白。任何针对测试故事的正则、姓名白名单、物品归属或情节节拍表，都会把通用引擎变成样例播放器，并且无法留下可检查的推断证据。

## 决策

1. Parse、Story State、对白抽取/赋格和 Director 的语义判断统一采用 `Prompt → JSON → Zod → 落盘`。每个阶段使用自己的严格 schema，拒绝未知字段和不在当前项目实体/镜头目录中的引用。
2. Director 只消费已确认的场、事件、时间、实体、状态和对白 ID；不得为了补信息再次读取原始剧本做语义扫描。原文只在摄入/对白抽取阶段作为证据输入。
3. 推断状态必须写在状态文件，`truth: inferred`，并保留当前状态覆盖的身份片段；不得回写实体 `visual.base`、描述或参考图。
4. 没有 Provider、Provider 失败或 JSON 校验失败时，降级逻辑只能复制原文、保持已有 Canon、按稳定顺序映射或返回空推断；不得生成故事特定事实，也不得把降级结果伪装成 LLM 推断。
5. 测试夹具可以包含公开故事文本，但只能位于 test/support 或测试文件中；生产模块不得包含样例故事的人名、专名、台词和情节正则。

## 后果

- 任何阶段的输入、输出、校验失败和降级都可审计，故事换成中文、科幻或原创文本时不会走到样例专用分支。
- 无 Provider 时状态不会自动“猜对”，用户会看到待处理/空推断，而不是错误的人设事实；这比静默污染 Canon 更安全。
- 语义质量由模型和 schema 契约承担，确定性代码只负责边界、顺序、引用完整性和文件一致性。
