## 1. 这一条链要产出什么

**一页 = 一次 Image API = 一张 PNG。**  
图里已经是漫画：分格、阅读顺序、同一角色、格间有叙事关系。不是四张静帧，也不是 CSS / 后期拼贴。

页是给人读的成品。镜（Shot）是页里的一格，用来编辑和锁定，不是单独对外的成片。

对照别人：

| 来源 | 学什么 | 不学什么 |
|------|--------|----------|
| 你给的四格成品 | 起承转合、一页一图、字在图上、机位每格在变 | 特定 Q 版人设 |
| baoyu-comic | 先出角色表再 `--ref` 生页；页级分镜；画风×情绪×版式 | 知识漫画默认班底、PDF、EXTEND 首次设置阻塞 |
| comic-guide-skill | 五段 prompt、格子类型、每页复读外貌 | 哆啦A梦/火影 IP、横版课件结构 |

```
粘贴/编辑故事

  → 补实体 visual.base / 参考图               [已有，要加强]

  → 角色设定图（每角色或本项目一张表）         [新，人可重跑/锁定]
  → 页导演：一场拆成若干「页」，每页 2–4 格     [新，替代「只出镜头列表」]
  → 人改页：格序、格类型、对白、版式           [新]
  → 编译一页 prompt（可打开看）               [改]
  → Image API 出这一页 PNG                    [改：单位是页]
  → 人看 Outputs：一页一图；不满意则改 prompt 或重跑本页
```

人确认点只保留三处，避免 baoyu 那种九步清单：

1. **确认解析**（已有）  
2. **确认页分镜**（新；可跳过，默认 AI 页导演）  
3. **看图 / 重跑 / 锁定**（已有 Workflow + Outputs，对象改成页）

不在「选画风」上阻塞整条链；用项目 `styles/default.json`，人随时能改。

## 3. 页怎么切

**导演按场切页，不按「每 4 个 shot 切一刀」。**

一场可以是 1 页或多页。每页 2–4 格。默认优先 **四格起承转合**；高潮或物件特写可用 **三格（上二下一）** 或 **两格上下**。

每格有类型，不全是「电影机位」：

| 类型 | 用途 | 例子（《叶子》） |
|------|------|-----------------|
| establish | 交代空间/人物 | 病房、窗帘、床 |
| action | 推进情节的动作 | 拉开窗帘、拥抱 |
| insert | 关键物件特写 | 墙上那片叶 |
| reaction | 表情/态度变化 | Johnsy 说要活 |
| speech | 短对白为主 | 「它还在。」 |
| beat | 收束本页 | 点破「那是画的」 |

规则：

- 一页必须有一句 **页意**（这页在讲什么），四格都为它服务。  
- 禁止四格同机位、同情绪、对坐讲话。  
- 格与格要有信息增量（机位或情绪或物件至少变一样）。  
- 对白若进图：每泡 ≤ 15 字；长旁白不进像素，进页注。

旧 Shot 不扔：一场里 shot 仍按序存在，但 **归属某一页**（`page_id`）。重跑的是页，不是单格单独出一张成片图。

## 4. 生图怎么编（Compiler）

每页一份 prompt，五段，一次调用：

1. **画风**：项目 style.visual，每页整段复读。  
2. **版式**：例如「竖版或横版；4 格 2×2；黑框白沟；左上 1 → 右上 2 → 左下 3 → 右下 4」。  
3. **逐格**：位置 + 类型 + 场景 + 谁在场 + 动作 + 表情 + 机位 + 短对白。  
4. **文字**（若本页允许进字）：标题条 / 椭圆对白 / 心声云 / 拟声；禁止长段剧本。  
5. **一致**：每个出场角色复读 `visual.base`；若有角色表 PNG，adapter 走参考图；只画本格该出现的人。

Context Resolver 仍按格解析实体和连续性，但 Compiler **输出的是整页**，不是四份独立静帧 prompt。

Image adapter：

- 成功：`outputs/comics/pages/<pageId>/<runId>.png`  
- 页上未锁定的格共享这张图  
- 失败：页 failed，旧页图保留  
- 假 adapter 仍写真实 PNG（测试用）

**禁止**把四张不同静帧当产品页。磁盘上已有的旧静帧，只作遗留：可合成一张页图预览，或作废等重跑。新主链不再依赖合成器。

## 5. 角色怎么前后长得一样

两层，文字层已有，图层是缺口：

1. **Canon 文字**：`visual.base` + 服饰/状态。模型不得静默改 Canon。  
2. **角色设定图**（新）：对项目角色生成一张设定表（正面/侧面/表情或多人一表），写入该角色 `visual.references[]`。  
   生页时：Image API 若支持参考图就带上；不支持就把外貌句每格复读（现在这条已有雏形）。

先做「本项目一张总表」即可，不必一上来做每人多视图工厂。人可重跑、可替换参考图、可锁定。

不把哆啦A梦等 IP 当默认班底。角色来自故事实体。

## 6. 建议的数据（审查用，未写进 schema）

在现有 Scene / Shot / Entity 上加 **Page**，不另起一套大纲库。

**Page**：`id`、`scene_id`、`intent`（页意）、`layout`（四格 / 上二下一 / 两格）、`status`、`selected_image`、`locked`、`updatedAt`

**Shot（格）**：现有字段 + `page_id`、`panel_index`、`panel_kind`、可选 `speech`（短对白）

**Style**：现有 `visual` 足够第一刀；画风包（清线/日漫/水墨）和版式轴可后加，不进本刀必做。

**角色参考**：继续用 `visual.references[]`，约定一张 `sheet` 优先于散图。

Workflow 节点改挂 Page（或 Page 与其格共享一次 run）。人在 Workflow 点的是页。

| Story | 仍编场剧本、挂实体 |

## 9. 和现状的差

现在已经有：解析确认、实体、shot、context、整页 prompt 雏形、页图路径、Outputs 一页一图、旧静帧合成。

还缺、且必须先审的：

- Shot 仍是主对象，页是事后每 4 镜切一刀  
- Prompt 仍是 purpose/action/camera，没有页意、格类型、起承转合  
- 图内文字仍按限制关掉  
- 没有角色设定图，也没有生页带参考图  
- 重跑语义仍像「重跑一个镜头」  

合成器只保留给旧文件，不再当漫画主链。
